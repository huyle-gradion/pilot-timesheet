# Agent-answered judgments

Use this when `log` reports a `judgment` (no judge is configured), when `log` exits because the judge is unusable (its key variable is not set), or when a stop says to answer a judgment through the agent path. In the last two cases run `"$TS_BINARY" next --do --date <day>` instead of `log`: it runs the same steps without the judge. Handle `ask_human`, `stopped` and `human_gates` exactly as in the skill. If a report shows `state: action`, run its `action.cmd` argv once, verbatim, and run the same command again. A `judgment` state is yours to answer: write only `judgment.answer_file`, copy its digest verbatim, then run the same command again with the same `--date`. A `last_error` means your last answer for this same content was rejected; fix exactly what it names. `judgment_failed` is a stop.

**`block_descriptions`**: judge only `judgment.draft.blocks`. Write `{"draft_digest":"<judgment.draft_digest>","notes":"<string>","descriptions":{"<block_id>":"<prose>"}}`, with one grouped-topic entry per block and no times, block fields or `PRs:` list (the binary appends it). `outside_work_hours` is informational only.

**`classifications`**: use only `judgment.blocks[]` and `judgment.candidates[]`. For each interval pick at most one option from the set its block's `candidates` names, or omit it. Write `{"ledger_digest":"<judgment.ledger_digest>","selections":{"<interval_id>":{"catalog_id":"<set catalog_id>","classification_id":"<option id>"}}}`; the honest no-op is `{"ledger_digest":"<judgment.ledger_digest>","selections":{}}` (an answer without the digest is asked again). A saved-day recovery judgment carries no candidates: query `"$TS_BINARY" classifications --query "<topic>"` and copy the receipt's ids. Never invent an id.
